# packages/contracts

## Overview

The shared API contract: Zod schemas and their inferred types, used by the api for validation and by the web to parse every `/api` answer (`apiRequest` in `apps/web/src/api/client.ts`). There is no OpenAPI document or generated client; spec 0007 brings OpenAPI back with the public API.

## Stack

TypeScript, Zod (`catalog:` version). Built to `dist/` with `tsc`; consumers import the built output, so build before typechecking dependents (Turborepo handles this).

## Commands

```bash
pnpm --filter @ssdashboard/contracts build
pnpm --filter @ssdashboard/contracts test   # src/**/*.spec.ts and test/*.spec.ts
```

## Conventions

- One file per module's shapes (`src/health.ts`), re-exported from `src/index.ts`.
- A module with several pure parts is a folder: `src/customers/`, `src/orders/` (the state machines, amounts, and outcome rules, plus spec 0013's `order-api.ts` request and answer shapes, `order-reasons.ts` code lists, and `order-attention.ts`), `src/credit/`, `src/settlement/`, `src/tasks/`, `src/connectors/` (spec 0015: `connector-enums.ts`), `src/catalog/` (specs 0006 and 0012: `skus.ts` with the SKU code, create, edit, and the wider `SkuSummary` and `SkuDetail` rows carrying style, season, group, option values, and barcodes; `search.ts` with `SkuListQuery` (filters `seasonId` as a uuid or `none`, `productGroupId`, `styleId`) and `SkuListResponse`; `cost-basis.ts`), and `src/audit/` (the actor union and its six constructors, the entry and list shapes, the `AUDIT_ACTIONS` registry, and `AUDIT_RECORD_TYPES`, whose labels are `@ssdashboard/i18n` message keys; a new action names a listed record type, and a customer facing record type lists its personal keys), plus `src/platform/cost-rules.ts` beside `src/platform.ts` (with the cost rule routes' shapes, `RecordCostRuleBody`, `CostRuleRow`, `CostRulesResponse`, spec 0009 AC-23), `src/license/` (spec 0009: `LicenseEnvelope`, the strict `LicensePayload`, `bundlePhase` and the union rule per bundle, `LicenseSummary`, `LicenseNotice`; `license-phase.spec.ts` is the exhaustive boundary table; milestone 4 adds `license-notice-work.ts` (`LicenseDayNotice`, `noticeInDailyReport` for days 30, 14, 7 and every grace and wind down day, `licenseNoticeWork`: what stops and what continues until when, by the phase (`noticeWindsDown`: in `off` the `pre_lapse` work stops), with `capabilitiesStoppingAt`, the one rule of what stops that `staffNotices` shares, a cross bundle `requiresOneOf` included), `wind-down-scope.ts` (`inCarrierScope`, the carrier creation time and the pickup window; `WindDownScopeAnswer`; `HookDecision` and `hookDecision`, `process` or `ignored_unlicensed`), and `wind-down-report.ts` (`WindDownReport`, the reduced daily report contract for feature 25), tested in `wind-down.spec.ts`), and `src/settings/` (spec 0009: the settings registry, one file per screen group (`brand`, `policies`, and `catalog`, whose rows milestone 5 added for specs 0012 to 0015), `SETTINGS_REGISTRY` and the `SettingKey` and `SettingValues` types, `PUBLIC_CONFIG_FIELDS`, `settingWriteIssues` (rules across settings), `nestsDeeperThan`, and the `GET` and `PUT /api/settings` shapes; an entry with `onInvalid: 'refuse'` fails closed on business reads; `registry.spec.ts` checks every entry, including that a `sqlRead` key has a seed row in `packages/db/migrations` and both catalogs label it; the settings API also holds `OffImpact`, the off dialog's answer, `SettingStepView` and `StepTurnOn` (an executing step entry's capability, `notifiesCustomer`, and turn on check, with `NO_STOCK_OUT_SOURCE`); `registry.spec.ts` also holds every entry to the free text rule, failing closed: a string needs a `regex` check or a fixed shape format (uuid, ISO date, datetime, time), and any schema type it does not know is a problem), and `src/modules/` (spec 0009 milestone 3: `ModuleDefinition` and `CapabilityDefinition` (`bundle`, `kind`, `windDown`, `requiresOneOf`, `workOf`, `steps`), `MODULE_REGISTRY` (only modules and capabilities whose code exists: a row lands with its code), `moduleRegistryIssues` (the AC-6 rules; the api checks the module folders), `moduleToggleSetting` (the `module.<key>.enabled` entry of a toggleable module), the pure `moduleStates` (rules 1 to 7 and S1 to S4; a module is never `limited`; `requires_off` when a required module is not `on`) with `openItemCuts`, `isRunnableState`, and `compareInstants` (UTC ISO instants compared by their text, microseconds included), and `ModuleStatesResponse`, `externalModuleStateView` (key and state only, for callers without an internal hat), `staffNotices`, `backfill.ts` (`BackfillGap` with its `BackfillCause`, `BACKFILL_MARKER`, and `actsOnEvent`, the step watermark of AC-27), and the module error codes and bodies (`ModuleLimitedError`, `ModuleRequiredByError`, `ModuleRequiresError`); a module key is one lowercase word; `module-state.spec.ts` is the exhaustive table). One file per concern. Each file is re-exported from `src/index.ts`, so consumers import from the package root, not from the folder path.
- The enums in `src/orders/`, `src/customers/`, `src/credit/`, `src/settlement/`, `src/tasks/`, `src/connectors/`, and `src/platform/cost-rules.ts`, plus `LedgerSourceType` and `ReservationStatus` (`src/inventory.ts`), `CostBasis` (`src/catalog/cost-basis.ts`), `LocationOwnerType` and the owner type policy enums `SaleRecordedAt`, `RefundBy`, `TaxDocument` (`src/locations.ts`, beside the owner policy shapes of spec 0009 AC-24: `OwnerPolicyFields`, `OWNER_POLICY_LOCKED_FIELDS`, `OwnerPolicyView`, `PutOwnerPolicyBody`), `StockReceiptStatus` (`src/stock-receipts.ts`), and the license source, check trigger, check outcome, and phase enums (`src/license/`), match the database enums of the same meaning (for example `FulfillmentState` and `orders.fulfillment_state`). `packages/db/test/enum-parity.e2e-spec.ts` fails when one drifts. Keep both in step in one change.
- Every reason, outcome, or account code on append only history is a `ReasonCode` (`src/orders/order-states.ts`), the twin of the database's `reasonCodeShape` check: a code, never a typed note. Settlement's two free text fields are capped at 500 characters (`SettlementPartnerText`, `SettlementPaymentReference`), like their database checks.
- `deriveOrderOutcome` is the only place an order outcome is computed. Never set `orders.outcome` by hand.
- `InvalidPhone` never carries the input text (Law 151). Never put raw phone text into an error message or a log line.
- Schemas are the source of truth; export types with `z.infer`, never a hand written duplicate.
- ESM with NodeNext resolution: relative imports need the `.js` suffix.
- Money never touches a float. Amounts and unit costs cross boundaries as `numeric` text (`MoneyString`, `UnitCostString`) and are parsed into `Money` (cents) and `UnitCost` (ten thousandths) on bigints; every rounding is half away from zero, once. Line totals come from `LineAmounts.compute` (`src/money.ts`).
- Typed numbers at an input edge use `quantityInput`, `moneyInput(digits)`, and `westernDigits` (`src/digit-input.ts`, built on `@ssdashboard/i18n`), so Arabic digits and separators are normalized before the range rules run (spec 0004 AC-18). Never on passwords, tokens, names, search, free text, or response schemas.
- Localized text is `LocalizedText` (`{ en?, ar? }`, `src/localized-text.ts`); reuse it for every `jsonb` name or description field.
- The web calls `/api` with `fetch` and parses the answer with the contract schema (`ConfigResponse.parse`, or `apiRequest(method, path, Schema)`); if OpenAPI is added later, that feature migrates those calls.
