# Platform

Services every module shares: brand settings, the signed license, gap free document numbers, the per order cost rules, the audience and permission guards, request validation pipes, and the public client config route.

## Owns

- `GET /api/config`, open to everyone, serving only the `public_config` registry entries (spec 0009, AC-5): [config.controller.ts](config.controller.ts)
- Brand settings typed by the registry in `@ssdashboard/contracts` (`packages/contracts/src/settings/`), in [settings/](settings/):
  - `SettingsService`, the only reader and writer of `settings` ([settings/settings.service.ts](settings/settings.service.ts)): `read(keys)` and `get(key)` return the registry default for a key with no row, and for a row that fails its schema (logged once by key, never the value; `invalid` in the staff read), except that `read` and `get` of an entry marked `onInvalid: 'refuse'` (the inventory lock date and the document prefixes) throw `SettingUnreadable` so the work stops; a read given a transaction goes to the database, any other read to the cache; `write` refuses a value nested deeper than 16 levels, checks the value, the reason rule, `expectedUpdatedAt`, and the rules across settings (`settingWriteIssues`: the default language stays enabled, only languages with a catalog) under one advisory lock, writes nothing for an unchanged value, and otherwise writes the row, the `setting.changed` audit entry (its `before` is the fixed `{ invalid: true }` when the stored row fails its schema, never the corrupt content), `NOTIFY ssd_platform_changed`, and the `platform.reconcile_modules` job in one transaction. Also `localDate` in the install time zone
  - `SettingsCache` (30 seconds per key) and `PlatformChangesListener` (one dedicated connection running `LISTEN ssd_platform_changed` in the api and the worker, dropping cached keys on each notification, with TCP keepalive whose first probe goes out after 10 seconds idle, so a silently dropped connection errors once the operating system's probes go unanswered (minutes by OS defaults) and is then reconnected, and a 5 second connect timeout, reconnecting with a doubling delay (`LISTENER_RETRY`, overridable in tests) and dropping the whole cache once back): [settings/settings-cache.ts](settings/settings-cache.ts), [settings/platform-changes-listener.ts](settings/platform-changes-listener.ts)
  - `GET /api/settings`, `PUT /api/settings/:key`, and `GET /api/settings/:key/off-impact`, staff with `settings.manage`: [settings/settings.controller.ts](settings/settings.controller.ts), the body checked by [settings/put-setting-body.pipe.ts](settings/put-setting-body.pipe.ts) (422 `SETTING_INVALID` for a bad or too deep value, `REASON_TOO_LONG`, `VALIDATION_FAILED`). The list and the write serve every registry setting plus each toggleable module's switch `module.<key>.enabled` (group `modules`, derived from the module registry by `moduleToggleSetting`; none exists until a toggleable module lands). A toggle is written like any setting (409 `NOT_LICENSED` for a module of an unlicensed bundle, either way); under the advisory lock `ssd.settings.modules`, and only once the value really changes, turning a module off that another `on` module requires answers 409 `MODULE_REQUIRED_BY` with `dependants`, turning one on while a module it requires is not `on` answers 409 `MODULE_REQUIRES` with `requires`, and turning one back on hands the reconcile job the gap it was off for (its backfill)
  - The `platform.reconcile_modules` queue (`RECONCILE_MODULES_JOB`, policy `short`, owned by the core capability `platform.reconcile_modules`): `ReconcileModulesProducer`, provided only in the api by [platform-api.module.ts](platform-api.module.ts) (the worker never writes a setting), makes the api's send only client and the queue ready at bootstrap (5 second connect timeout) and enqueues inside the write transaction (`JobSender.sendIn`, pg-boss `fromDrizzle`); a resumed module's job carries its gap and its own singleton key. The worker's `ModuleJobSupervisor` works it: [settings/reconcile-modules.queue.ts](settings/reconcile-modules.queue.ts)
- Modules, capabilities, and the gate (spec 0009, AC-6 to AC-13, AC-26, AC-30), in [modules/](modules/), over the registry and the pure `moduleStates` of `@ssdashboard/contracts` (`packages/contracts/src/modules/`):
  - `ModuleRegistry` ([modules/module-registry.ts](modules/module-registry.ts)): the rows from `MODULE_ROWS` (`MODULE_REGISTRY` in every process; a test overrides the token to add fixture modules), a capability with its module, the settings definitions widened with the module toggles, and `alwaysOn(key)` (a core module without a toggle, or its core capability with no `requiresOneOf`), which lets the gate, the state service, and the job gate skip every read for the modules of today
  - `ModuleStateService` ([modules/module-state.service.ts](modules/module-state.service.ts)): every module's, capability's, and executing step's state from `LicenseService.bundleFacts()` (the live phases, the lapse instants, the last renewal), the toggle and step settings, and the `openItems` hooks of `until_closed` capabilities; a snapshot (with today's license notices beside it, `notices()`) cached at most 30 seconds and dropped with the settings cache (every `NOTIFY ssd_platform_changed`) and on `LicenseChanged`; callers that miss it at the same generation share one computation. A module's own state is never `limited` (it reads `read_only` while only its finishing capabilities are `limited`), and a module whose required module is not `on` reads `read_only` with reason `requires_off`, its capabilities too. `isOn`, `isRunnable` (`on` or `limited`), `assertOn`, and `assertMayFinish(key, recordOpenedAt)` throw the domain errors `ModuleOff` and `ModuleLimited` ([modules/module.errors.ts](modules/module.errors.ts), mapped by `moduleHttpError` to 404 `MODULE_OFF` and 409 `MODULE_LIMITED` with `before`)
  - `@RequiresModule(key)` and `@RequiresCapability(key)` ([modules/requires-module.decorator.ts](modules/requires-module.decorator.ts)): exactly one on every controller class, a handler may narrow to a capability of the same module; [modules/requires-module.spec.ts](modules/requires-module.spec.ts) fails the build otherwise, and [modules/module-folders.spec.ts](modules/module-folders.spec.ts) for a registry module without its `src/<key>/<key>.module.ts` or such a folder without a row (`config` and `database` are infrastructure)
  - `ModuleGate` ([modules/module.gate.ts](modules/module.gate.ts)), the fourth global guard (registered in `identity.module.ts` after the permission guard): 404 `MODULE_OFF` for every route of an `off` module or capability and every non `GET` route of a `read_only` one; `limited` passes (the owning service refuses newer records with 409 `MODULE_LIMITED`); portal routes need `on` for new work and keep their `GET`s while `limited` or `read_only`; hook routes always pass; 500 `MODULE_MISSING` for a route without a known declaration
  - `GET /api/platform/modules`, any staff hat ([modules/modules.controller.ts](modules/modules.controller.ts)): every module's and capability's state, the caller's staff notices (`staffNotices`, internal hats only), and the license notices for `settings.manage` holders only. A caller who wears no internal hat (only `partner` or `media_buyer`) gets `key` and `state` alone, `since`, `before`, and `reason` null (W8)
  - `CapabilityHooks` ([modules/capability-hooks.ts](modules/capability-hooks.ts)): each capability's `openItems`, `backfill`, `onDisable`, and `offImpact`, registered from its module's `onModuleInit`, and the one outbound command port (`failWaitingCommands(capability, reason)`, the connectors module's from spec 0015; only a test fixture registers one today, so it answers zero); `OffImpactReader` ([modules/off-impact.ts](modules/off-impact.ts)) builds the off dialog's answer from them (value at cost only for `cost.view`, typed confirmation when a partner holds pieces; a hook or the port that throws answers 503 `OFF_IMPACT_UNAVAILABLE`, `OffImpactUnavailable` in [modules/module.errors.ts](modules/module.errors.ts))
- Jobs (spec 0009, AC-10, AC-11, AC-22), in [jobs/](jobs/): one pg-boss client per process, `JobBoss` ([jobs/job-boss.ts](jobs/job-boss.ts)): send only with a pool of 2 in the api (`JobsModule.forApi()`, imported by `PlatformApiModule`), working with a pool of 5 in the worker (`JobsModule.forWorker()`, imported by `WorkerModule`) ([jobs/jobs.module.ts](jobs/jobs.module.ts)). Every queue is a `defineQueue` constant with its owning capability ([jobs/job-declarations.ts](jobs/job-declarations.ts)); `JobSender` ([jobs/job-sender.ts](jobs/job-sender.ts)) stamps `data.capability` (and `data.step`) on every job; the worker's job providers declare their queue, keyed schedules, and handlers into `JobRegistry` ([jobs/job-registry.ts](jobs/job-registry.ts)) from `onModuleInit`. `ModuleJobSupervisor` ([jobs/module-job-supervisor.ts](jobs/module-job-supervisor.ts)) reconciles at worker start, on every `NOTIFY ssd_platform_changed` (the `license` payload included, through `PlatformChangesListener.subscribe`), on `LicenseChanged`, and in the `platform.reconcile_modules` job: schedules of runnable capabilities registered in the current `timezone` setting (re registered when it changes), others removed (`unschedule` by key), a stopped owner's workers stopped (`offWork`, not waiting) and its queued jobs cancelled, on a shared queue only the stopped capability's (`findJobs` by `data`, paged, then `cancel`), waiting commands failed with `MODULE_OFF` or `STEP_OFF`, `onDisable` called (again at a worker start while stopped: hooks are idempotent), and one backfill job per resumed capability on `platform.backfill` (singleton key on the gap, looked up first). Every job passes the gate: a stopped capability's or step's job completes with `{ skipped: 'MODULE_OFF' }` or `{ skipped: 'STEP_OFF' }`, never `failed`; a handler that throws is logged through `describeError` and fails its job with `JobHandlerFailed` (the capability and the error's name only). One queue that fails to reconcile never stops the others or the stop of a capability (the reconcile then fails, so its job retries); queued jobs are cancelled page by page until a page comes back empty (a warning past 1,000 pages); a step's jobs are cancelled by the registry's `steps` of every capability on the queue. [jobs/jobs-boundary.spec.ts](jobs/jobs-boundary.spec.ts) keeps `new PgBoss` to `JobBoss` and `boss.send` to `JobSender` and the supervisor. The queues today: `platform.reconcile_modules`, `platform.backfill`, `platform.license_check`, `ledger.reconcile`, `auth.cleanup`, `mail.send`
- The signed license (spec 0009, AC-14 to AC-17, AC-20, AC-26), in [license/](license/):
  - `LicenseVerifier` and the pure `verifyLicense` ([license/license-verifier.ts](license/license-verifier.ts)): at most 16 KB of UTF 8 JSON in the strict envelope, a key built into the image, a `devOnly` key only in a development build (`devKeysTrusted`: `NODE_ENV` not `production` and `APP_VERSION` `0.0.0-dev`, security review M2-1), an Ed25519 signature over exactly the payload bytes through `node:crypto`, the strict payload, and the install binding (client code and tenant id); it also gives the hash of the signed payload bytes. It never opens a network connection
  - The trusted public keys ([license/license-keys.ts](license/license-keys.ts)): only the committed development key `dev-1` (`devOnly`) in this release; the owner adds the production primary and standby public keys later (owner ruling 1, 2026-11-07)
  - `LicenseService` ([license/license.service.ts](license/license.service.ts)), the only writer of `licenses` and `license_checks`: `checkFile` (at api start through `LicenseStartCheck` in `PlatformApiModule`, at worker start and daily through `LicenseCheckJob` in the worker, whose queue and `daily` schedule on `LICENSE_CHECK_CRON` are declared through `JobRegistry` with the core capability `platform.license_check`), `upload`, `summary`, `notice(day)`, `windDown()`, `bundleFacts()` (the live phases, lapse instants, and last renewals `ModuleStateService` reads), and `licensedBundles()`. License dates are read with `to_char(…, 'YYYY-MM-DD')`, never `::text`, so a non ISO `DateStyle` cannot make a license grant nothing (security third check m2, S1) (the `licensed` flag of `GET /api/settings` and the 409 `NOT_LICENSED` of `PUT /api/settings/:key`). The entitlement is the union of the recorded licenses that still verify: a row counts only while its stored envelope verifies with the image's keys for this install and its term columns equal the signed payload (security review M2-2; checked once per row and process), so a row inserted by hand grants nothing and is logged once by id. Every read computes the phase live with `bundleStanding` (in `@ssdashboard/contracts`) from those licenses, today in the `timezone` setting, and the wind down end the latest check recorded (which only restricts); no `pre_lapse` capability exists yet, so the Operations wind down ends only by its length. A check runs under `pg_advisory_xact_lock(hashtext('ssd.license_check'))`, reads the clock after the lock, records one `license_checks` row with both phases as evidence, adds a verified license whose payload was not recorded before (with the `license.added` audit entry: the uploader, a `system_job` `platform.license_check` for the daily check, or `platform.license_start_check` for a start check), and, when a recorded phase moved from the latest check's (by `seq`, insert order), sends `NOTIFY ssd_platform_changed` with `license` and emits `LicenseChanged` after the commit. The same license again, whatever its envelope's whitespace, is `already_recorded`; the duplicate is looked for, under the lock, only among the rows that verify, so `payload_sha256` is not unique and a row planted with a genuine license's hash never stops that license from being recorded (security re-review R2). The file is opened non blocking and at most 16 KB plus one byte is read. A missing or bad file records its outcome and logs one error with the outcome and the file's SHA 256, never its content; recorded licenses keep counting. Time comes only from `PlatformClock` ([license/platform-clock.ts](license/platform-clock.ts), the database's `clock_timestamp()`); `clock_behind` is recorded, never enforced, and a wind down end stamped while the clock ran ahead stops counting once it is back
  - `GET` and `POST /api/platform/license`, staff with `settings.manage` ([license/license.controller.ts](license/license.controller.ts)): 200 with `changed: false` for a license that grants nothing new, 422 `LICENSE_INVALID` with the outcome, 413 `LICENSE_TOO_LARGE`
  - The vendor's signing command `sign-license` ([license/sign-license.ts](license/sign-license.ts), with `--warehouse-expires-on`) and `signLicense` ([license/license-signing.ts](license/license-signing.ts)); `pnpm bootstrap` uses it with the committed dev private key ([license/dev-license-key.pem](license/dev-license-key.pem)) to write `.env.license.json` and set `LICENSE_FILE`. That key is committed only because a release build or a production process refuses every license it signs (`devKeysTrusted`); a production private key never enters the repository, an image, or an install
- The 409 `NOT_LICENSED` of `PUT /api/settings/:key` (security finding S6, decided in milestone 2): `SettingsService.write` refuses an entry whose bundle is not licensed now, from the `licensed` set the controller reads from `LicenseService` (the license reads settings, so settings never inject it)
- The pg-boss schema name the one queue client of each process uses: [job-schema.ts](job-schema.ts)
- Gap free document numbers: [numbering.service.ts](numbering.service.ts); corrupt stored `document_prefixes` refuse the document (`DocumentPrefixesUnreadable`, 409 `DOCUMENT_PREFIXES_UNREADABLE` through `inventory/ledger-http.ts`)
- The per order cost rules in force on a day (`CostRulesService.ruleFor`, `not_set` and never 0 when no rule is set): [cost-rules.service.ts](cost-rules.service.ts), selection in [cost-rule-selection.ts](cost-rule-selection.ts)
- `@Audience(...)` and the deny by default guard: [audience/audience.decorator.ts](audience/audience.decorator.ts), [audience/audience.guard.ts](audience/audience.guard.ts)
- One permission declaration per route and its guard (spec 0008): `Access`, the immutable value object of what the caller may do ([access/access.ts](access/access.ts)), `@Permission(...)` and `@AnyHat()` ([access/permission.decorator.ts](access/permission.decorator.ts)), `@CurrentAccess()` ([access/current-access.decorator.ts](access/current-access.decorator.ts)) and `PermissionGuard` ([access/permission.guard.ts](access/permission.guard.ts)). It reads `request.access`, which identity's session guard sets, and never queries the database

## Never touches

- Ledger tables or the ledger service.
- Business rules of any module. It offers shared tools only.
- Another module's tables.

## How to test

```bash
pnpm --filter @ssdashboard/api test -- src/platform
pnpm --filter @ssdashboard/api build
pnpm --filter @ssdashboard/api exec vitest run --config ./vitest.config.e2e.ts test/numbering-reconcile.e2e-spec.ts test/cost-rules.e2e-spec.ts test/settings.e2e-spec.ts test/settings-cache.e2e-spec.ts test/license.e2e-spec.ts test/license-worker.e2e-spec.ts test/module-off-no-orphaned-jobs.e2e-spec.ts
```

`license.e2e-spec.ts` runs the api with `NODE_ENV=production`, a fixed `PlatformClock`, and a vendor key made in the test beside the committed dev key (`LICENSE_KEY_SET` overridden through `test/license-support.ts`, which the settings suites use to record an Operations license); `license-worker.e2e-spec.ts` boots `WorkerModule` for the start check, the schedule, and the daily handler; [license/license-verifier.spec.ts](license/license-verifier.spec.ts) proves each verifier outcome, and `bundlePhase`'s boundary table is `packages/contracts/src/license/license-phase.spec.ts`.

[audience/audience.spec.ts](audience/audience.spec.ts) fails the build for a controller without exactly one `@Audience(...)`, [access/permission.spec.ts](access/permission.spec.ts) for a `staff` or `partner` handler without exactly one valid permission declaration, and [modules/requires-module.spec.ts](modules/requires-module.spec.ts) for a controller without exactly one module declaration of its own module.

`module-off-no-orphaned-jobs.e2e-spec.ts` runs the api and the worker graph in process with the fixture modules of `test/fixtures/fixture-operations.module.ts` (an Operations module with a queue, a schedule, queued jobs, a waiting command, hooks, and two `until_closed` capabilities; a core module owning a shared queue with a Warehouse capability on it) through `MODULE_ROWS`: off with no orphaned jobs, back on with schedules restored in the current time zone and one backfill, the off dialog and work in flight, the shared queue rule, and every registered capability used. `license.e2e-spec.ts` also runs an api whose connections use `DateStyle=German`. The pure state rules are `packages/contracts/src/modules/module-state.spec.ts` (exhaustive) and the gate, state service, and supervisor have unit specs beside them.

## Decisions

- The projection rule (A6): a module publishes a past tense domain event inside its own transaction, and no module reads another module's table to fill an order projection column (`orders.write_back_state`, `returned_credit_amount`, `exchange_consumed_amount`, the cash amounts). See [0002 tenancy child](../../../../docs/specs/0002-core-data-model/0002-tenancy-platform.md).

- A setting's audit record id is a name based (version 5) uuid of its key (`settingRecordId`), because `audit_entries.record_id` is a uuid and `settings` rows have none; the entry's label carries the key.
- Every job of the worker shares one pg-boss client and is declared through `JobRegistry`; the supervisor, never a job, schedules, so a `timezone` change re registers every cron within moments (review R11, closed in spec 0009 milestone 3). Schedules carry a `key` (`nightly`, `daily`): an install upgraded from an earlier release still holds the old unkeyed ones, which the first reconcile removes because no declaration names their empty key.
- The backfill of a resumed module runs on the platform's own queue `platform.backfill` (owned by `platform.reconcile_modules`, its jobs carrying the backfilled capability), not on a queue each capability would have to declare; the supervisor looks for a job with the gap's singleton key in any state before it sends, so a second reconcile of the same gap adds none.
- `onDisable` runs when a capability stops and again at each worker start while it stays stopped: the supervisor keeps what it last saw in memory only (no table), so the hooks must be idempotent.
- The module gate is registered in `identity.module.ts` beside the other global guards, because their order is the order of registration there and it must run last.
- A license file or upload that does not verify still writes its `license_checks` row (support evidence, and the manager's banner reads it), so an upload refused with 422 is a recorded check. The summary's `lastCheck` is the latest check of the file (an upload answers for itself). Its bundle phases, the notices, `windDown()`, and `licensedBundles()` are computed live from the licenses that verify (security review M2-2, M2-8); a check's recorded phases are evidence and decide only when `LicenseChanged` is emitted.
- `SettingsService` takes its audit writer without `@Optional()`, so a missing one fails at boot. Its job producer is `@Optional()` and api only (`PlatformApiModule`, imported by `AppModule` alone), so the worker never opens the send client; a missing producer fails the first write, which only the api serves.
