# Platform

Services every module shares: brand settings, the signed license, gap free document numbers, the per order cost rules, the audience and permission guards, request validation pipes, and the public client config route.

## Owns

- `GET /api/config`, open to everyone, serving only the `public_config` registry entries (spec 0009, AC-5): [config.controller.ts](config.controller.ts)
- Brand settings typed by the registry in `@ssdashboard/contracts` (`packages/contracts/src/settings/`), in [settings/](settings/):
  - `SettingsService`, the only reader and writer of `settings` ([settings/settings.service.ts](settings/settings.service.ts)): `read(keys)` and `get(key)` return the registry default for a key with no row, and for a row that fails its schema (logged once by key, never the value; `invalid` in the staff read), except that `read` and `get` of an entry marked `onInvalid: 'refuse'` (the inventory lock date and the document prefixes) throw `SettingUnreadable` so the work stops; a read given a transaction goes to the database, any other read to the cache; `write` refuses a value nested deeper than 16 levels, checks the value, the reason rule, `expectedUpdatedAt`, and the rules across settings (`settingWriteIssues`: the default language stays enabled, only languages with a catalog) under one advisory lock, writes nothing for an unchanged value, and otherwise writes the row, the `setting.changed` audit entry (its `before` is the fixed `{ invalid: true }` when the stored row fails its schema, never the corrupt content), `NOTIFY ssd_platform_changed`, and the `platform.reconcile_modules` job in one transaction. Also `localDate` in the install time zone
  - `SettingsCache` (30 seconds per key) and `PlatformChangesListener` (one dedicated connection running `LISTEN ssd_platform_changed` in the api and the worker, dropping cached keys on each notification, with TCP keepalive whose first probe goes out after 10 seconds idle, so a silently dropped connection errors once the operating system's probes go unanswered (minutes by OS defaults) and is then reconnected, and a 5 second connect timeout, reconnecting with a doubling delay (`LISTENER_RETRY`, overridable in tests) and dropping the whole cache once back): [settings/settings-cache.ts](settings/settings-cache.ts), [settings/platform-changes-listener.ts](settings/platform-changes-listener.ts)
  - `GET /api/settings` and `PUT /api/settings/:key`, staff with `settings.manage`: [settings/settings.controller.ts](settings/settings.controller.ts), the body checked by [settings/put-setting-body.pipe.ts](settings/put-setting-body.pipe.ts) (422 `SETTING_INVALID` for a bad or too deep value, `REASON_TOO_LONG`, `VALIDATION_FAILED`)
  - The `platform.reconcile_modules` queue: `ReconcileModulesProducer`, provided only in the api by [platform-api.module.ts](platform-api.module.ts) (the worker never writes a setting), starts at bootstrap (5 second connect timeout) and enqueues inside the write transaction (pg-boss `fromDrizzle`), `ReconcileModulesWorker` works it in the worker, a no op until spec 0009 milestone 3: [settings/reconcile-modules.queue.ts](settings/reconcile-modules.queue.ts)
- The signed license (spec 0009, AC-14 to AC-17, AC-20, AC-26), in [license/](license/):
  - `LicenseVerifier` and the pure `verifyLicense` ([license/license-verifier.ts](license/license-verifier.ts)): at most 16 KB of UTF 8 JSON in the strict envelope, a key built into the image, a `devOnly` key only in a development build (`devKeysTrusted`: `NODE_ENV` not `production` and `APP_VERSION` `0.0.0-dev`, security review M2-1), an Ed25519 signature over exactly the payload bytes through `node:crypto`, the strict payload, and the install binding (client code and tenant id); it also gives the hash of the signed payload bytes. It never opens a network connection
  - The trusted public keys ([license/license-keys.ts](license/license-keys.ts)): only the committed development key `dev-1` (`devOnly`) in this release; the owner adds the production primary and standby public keys later (owner ruling 1, 2026-11-07)
  - `LicenseService` ([license/license.service.ts](license/license.service.ts)), the only writer of `licenses` and `license_checks`: `checkFile` (at api start through `LicenseStartCheck` in `PlatformApiModule`, at worker start and daily through `LicenseCheckJob` in the worker), `upload`, `summary`, `notice(day)`, `windDown()`, and `licensedBundles()` (the `licensed` flag of `GET /api/settings` and the 409 `NOT_LICENSED` of `PUT /api/settings/:key`). The entitlement is the union of the recorded licenses that still verify: a row counts only while its stored envelope verifies with the image's keys for this install and its term columns equal the signed payload (security review M2-2; checked once per row and process), so a row inserted by hand grants nothing and is logged once by id. Every read computes the phase live with `bundleStanding` (in `@ssdashboard/contracts`) from those licenses, today in the `timezone` setting, and the wind down end the latest check recorded (which only restricts); no `pre_lapse` capability exists yet, so the Operations wind down ends only by its length. A check runs under `pg_advisory_xact_lock(hashtext('ssd.license_check'))`, reads the clock after the lock, records one `license_checks` row with both phases as evidence, adds a verified license whose payload was not recorded before (with the `license.added` audit entry: the uploader, a `system_job` `platform.license_check` for the daily check, or `platform.license_start_check` for a start check), and, when a recorded phase moved from the latest check's (by `seq`, insert order), sends `NOTIFY ssd_platform_changed` with `license` and emits `LicenseChanged` after the commit. The same license again, whatever its envelope's whitespace, is `already_recorded`; the duplicate is looked for, under the lock, only among the rows that verify, so `payload_sha256` is not unique and a row planted with a genuine license's hash never stops that license from being recorded (security re-review R2). The file is opened non blocking and at most 16 KB plus one byte is read. A missing or bad file records its outcome and logs one error with the outcome and the file's SHA 256, never its content; recorded licenses keep counting. Time comes only from `PlatformClock` ([license/platform-clock.ts](license/platform-clock.ts), the database's `clock_timestamp()`); `clock_behind` is recorded, never enforced, and a wind down end stamped while the clock ran ahead stops counting once it is back
  - `GET` and `POST /api/platform/license`, staff with `settings.manage` ([license/license.controller.ts](license/license.controller.ts)): 200 with `changed: false` for a license that grants nothing new, 422 `LICENSE_INVALID` with the outcome, 413 `LICENSE_TOO_LARGE`
  - The vendor's signing command `sign-license` ([license/sign-license.ts](license/sign-license.ts), with `--warehouse-expires-on`) and `signLicense` ([license/license-signing.ts](license/license-signing.ts)); `pnpm bootstrap` uses it with the committed dev private key ([license/dev-license-key.pem](license/dev-license-key.pem)) to write `.env.license.json` and set `LICENSE_FILE`. That key is committed only because a release build or a production process refuses every license it signs (`devKeysTrusted`); a production private key never enters the repository, an image, or an install
- The 409 `NOT_LICENSED` of `PUT /api/settings/:key` (security finding S6, decided in milestone 2): `SettingsService.write` refuses an entry whose bundle is not licensed now, from the `licensed` set the controller reads from `LicenseService` (the license reads settings, so settings never inject it)
- The pg-boss schema name every queue client uses: [job-schema.ts](job-schema.ts)
- Gap free document numbers: [numbering.service.ts](numbering.service.ts); corrupt stored `document_prefixes` refuse the document (`DocumentPrefixesUnreadable`, 409 `DOCUMENT_PREFIXES_UNREADABLE` through `inventory/ledger-http.ts`)
- The per order cost rules in force on a day (`CostRulesService.ruleFor`, `not_set` and never 0 when no rule is set): [cost-rules.service.ts](cost-rules.service.ts), selection in [cost-rule-selection.ts](cost-rule-selection.ts)
- `@Audience(...)` and the deny by default guard: [audience/audience.decorator.ts](audience/audience.decorator.ts), [audience/audience.guard.ts](audience/audience.guard.ts)
- One permission declaration per route and its guard (spec 0008): `Access`, the immutable value object of what the caller may do ([access/access.ts](access/access.ts)), `@Permission(...)` and `@AnyHat()` ([access/permission.decorator.ts](access/permission.decorator.ts)), `@CurrentAccess()` ([access/current-access.decorator.ts](access/current-access.decorator.ts)) and `PermissionGuard` ([access/permission.guard.ts](access/permission.guard.ts)). It reads `request.access`, which identity's session guard sets, and never queries the database
- Request validation: [zod-body.pipe.ts](zod-body.pipe.ts), [zod-query.pipe.ts](zod-query.pipe.ts)
- Keyset paging cursors: [keyset-cursor.ts](keyset-cursor.ts)
- Mapping query errors to answers: [query-error.filter.ts](query-error.filter.ts)
- Auth events other modules can listen to: [events/auth-events.ts](events/auth-events.ts)
- The settings, document counter, custom field, order cost rule, and license tables (`licenses` and `license_checks`, both append only; `install` too, written only by `migrate`, which also seeds one `not_set` rule per kind), defined in [packages/db](../../../../packages/db/src/schema/platform.ts)

## Never touches

- Ledger tables or the ledger service.
- Business rules of any module. It offers shared tools only.
- Another module's tables.

## How to test

```bash
pnpm --filter @ssdashboard/api test -- src/platform
pnpm --filter @ssdashboard/api build
pnpm --filter @ssdashboard/api exec vitest run --config ./vitest.config.e2e.ts test/numbering-reconcile.e2e-spec.ts test/cost-rules.e2e-spec.ts test/settings.e2e-spec.ts test/settings-cache.e2e-spec.ts test/license.e2e-spec.ts test/license-worker.e2e-spec.ts
```

`license.e2e-spec.ts` runs the api with `NODE_ENV=production`, a fixed `PlatformClock`, and a vendor key made in the test beside the committed dev key (`LICENSE_KEY_SET` overridden through `test/license-support.ts`, which the settings suites use to record an Operations license); `license-worker.e2e-spec.ts` boots `WorkerModule` for the start check, the schedule, and the daily handler; [license/license-verifier.spec.ts](license/license-verifier.spec.ts) proves each verifier outcome, and `bundlePhase`'s boundary table is `packages/contracts/src/license/license-phase.spec.ts`.

[audience/audience.spec.ts](audience/audience.spec.ts) fails the build for a controller without exactly one `@Audience(...)`, and [access/permission.spec.ts](access/permission.spec.ts) for a `staff` or `partner` handler without exactly one valid permission declaration.

## Decisions

- The projection rule (A6): a module publishes a past tense domain event inside its own transaction, and no module reads another module's table to fill an order projection column (`orders.write_back_state`, `returned_credit_amount`, `exchange_consumed_amount`, the cash amounts). See [0002 tenancy child](../../../../docs/specs/0002-core-data-model/0002-tenancy-platform.md).

- A setting's audit record id is a name based (version 5) uuid of its key (`settingRecordId`), because `audit_entries.record_id` is a uuid and `settings` rows have none; the entry's label carries the key.
- The daily license check (`LicenseCheckJob`) schedules itself with its own pg-boss client and reads the `timezone` setting once at worker start, like `ReconcileJob` and `AuthCleanupJob`. Spec 0009 milestone 3 moves it onto `JobRegistry`, whose supervisor re registers schedules in the current time zone.
- A license file or upload that does not verify still writes its `license_checks` row (support evidence, and the manager's banner reads it), so an upload refused with 422 is a recorded check. The summary's `lastCheck` is the latest check of the file (an upload answers for itself). Its bundle phases, the notices, `windDown()`, and `licensedBundles()` are computed live from the licenses that verify (security review M2-2, M2-8); a check's recorded phases are evidence and decide only when `LicenseChanged` is emitted.
- `SettingsService` takes its audit writer without `@Optional()`, so a missing one fails at boot. Its job producer is `@Optional()` and api only (`PlatformApiModule`, imported by `AppModule` alone), so the worker never opens the send client; a missing producer fails the first write, which only the api serves.

Record other non obvious decisions as ADRs in docs/adr/ and link them here.
