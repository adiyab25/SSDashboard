# apps/api/src/inventory

## Overview

The inventory module and its ledger service, the only writer of stock in the system. Every stock change in every module is a posting through `LedgerService` (`post`, `reverse`, `postCarrierShipment`); reads (`getLevels`, `getAvailable`, `reservationsFor`, `postingFor`) and reservations (`transaction` with `reserveLines`, `releaseLines`, `releaseSource`; the old one line `reserve` and `release` stay) live here too. The full contract is [spec 0002](../../../../docs/specs/0002-core-data-model/index.md).

## Conventions

- Only this folder may touch `movement_groups`, `stock_movements`, `movement_serials`, `stock_levels`, `reservations`, and `serials`. A lint rule in `apps/api/eslint.config.js` and the module wall, `apps/api/src/module-boundary.spec.ts`, enforce it.
- Every writer of balances, reservations, or discrepancies runs inside `ledgerTransaction` and takes `lockPairs` for each SKU and location before it reads or locks any balance or reservation row. A new writer that skips either breaks the AC-4 reserved stock check or can deadlock.
- Money is `Money` and `UnitCost` from `@ssdashboard/contracts` (bigint, rounded once, half away from zero). Cost rules change in `costing.ts` only, with a test per rule, never inline in SQL.
- Dates are compared in SQL against the stored values (`effective_at`, `recorded_at`, which the database sets), and calendar dates use the `timezone` setting (Africa/Cairo); never parse timestamps in JS for a rule. The `inventory_lock_date` governs the operating day the trigger stamped on the posting (`operating_day`, Cairo day with `operating_day_cutoff_hour`, read back by `RETURNING`), never the plain calendar date: with cutoff 3 and a lock date of 30 September, a posting at 01:00 on 1 October is `PeriodLocked` and one at 04:00 is accepted (review R5, `ledger.e2e-spec.ts`). The lock date is read with `SettingsService.get('inventory_lock_date', tx)`, which fails closed: a stored value that fails its schema refuses every posting with `LockDateUnreadable` (409 `LOCK_DATE_UNREADABLE`), never reads as "nothing locked" (spec 0009, security review S1).
- Movements are never updated or deleted. A correction is `reverse`, which writes opposite movements costed by the normal rules.
- A SKU archive, unarchive, or code change and a location edit, archive, or unarchive records its audit entry (`sku.*`, `location.*`, spec 0010) through `AuditService.record` inside the same `ledgerTransaction`, only when the record really changed; the services take the caller (`SkuCaller`, `LocationCaller`) for the actor.
- Reservations are written only inside `LedgerService.transaction` (a `StockTransaction`, spec 0011 AC-5; the functions refuse a transaction the runner did not open with `InvalidInput`). Calling `transaction`, `post`, `reverse`, or `postCarrierShipment` inside a running stock transaction raises `NestedStockTransaction` and fails the outer transaction even if `work` swallows it; pass the open transaction down. `work` can rerun once after a deadlock, so keep no state across it. Order inside: the caller's rows, then `loadMaster` (`FOR SHARE`), then `lockPairs`, then reservation rows; the releases read their rows without a lock first to learn the keys, then lock pairs, then lock the rows.
- Filling (AC-21): every write that frees stock at a key (an inbound line of any source type, a reversal of an outbound, a release) fills that key's waiting demand, oldest first (`created_at`, `id`), in the same transaction, and publishes `ReservationFilled`. `free` is on hand less held over sellable places (`buildAvailabilitySql`).
- Two exceptions let on hand fall below what orders hold, each announced by an event in the same transaction: a carrier shipment (`postCarrierShipment`, AC-22) may also take on hand below zero where negative is not allowed (`StockOverdrawn`), and a `damaged` or `missing` removal (AC-23, milestone 4). Both then run `shortenExcess`, which moves held quantity of the newest other reservations to unfilled (`ReservationShortened`). `postCarrierShipment` is never refused for stock, reservations, an archived SKU or location, or a locked period (its time moves to now), and it cannot post a lot or serial tracked SKU.
- SKU rows are locked and read only through `CatalogService.lockForShare`, `lockForUpdate`, and `serialTrackedVariantIds` (AC-18); never name `product_variants` here.
- Throw `LedgerError` with a code for every rule a caller can break; plain `Error` is only for "cannot happen" states.
- `sellable_online` changes only through `OnlineLocationService` (gate actions) and the archive that clears it; never in create or edit. A reservation write sets `updated_at = now()` (the online change feed reads it). `changedSince` trusts that every ledger write commits within seconds; the watermark trails the clock by `ONLINE_FEED_LAG`.
- Never branch on an owner type. Ask `LocationPolicyService.policyFor(locationId)` and read an attribute (`handoverIsSale`, `saleRecordedAt`, `stockOwnedByBrand`, ...). A new owner type difference is a new policy column, not an `if`. Owner type and party never change after creation (trigger `locations_owner_fixed`); a closed shop gets a new location.
- Writers never pass `operating_day` on `movement_groups` or `stock_movements`: a trigger stamps it from `effective_at` (Cairo day, cutoff hour from settings). Source types are the list in `LedgerSourceType`; a restock posts at the shipped line's frozen unit cost, never the balance average.

## Gotchas

- Run the database suites after any change here: `pnpm build && pnpm --filter @ssdashboard/api test:e2e`. They check after every test that each balance still equals its movement sums.
- A lot tracked SKU is posted and reserved by lot only; a reservation's lot must equal the shipping line's lot.
- `rebuildLevel` fixes only `balance` discrepancies; reservation and serial ones raise `NotRebuildable` and stay open until the discrepancy screen (spec 0011 milestone 5) adds a dismiss action.
- The nightly reservation check compares held quantity with `max(onHand, 0)`: a carrier shipment may leave on hand below zero with nothing held, which is not drift.
