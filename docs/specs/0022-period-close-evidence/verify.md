# 0022 verify: period close with evidence

How `/check verify` proves each acceptance criterion of [index.md](index.md). Every Bosta fact comes from spec 0018's recorded fixtures and spec 0020's fixture sheets; no check calls Bosta or Shopify. "e2e" means `pnpm --filter @ssdashboard/api exec vitest run --config ./vitest.config.e2e.ts <file>` against Postgres. The two worked months of [rationale.md](rationale.md) are the shared fixtures `apps/api/test/fixtures/settlement-november-per-delivery.ts` and `settlement-november-per-transaction.ts`; their figures follow spec 0020 AC-31 (cash outs are negative lines, never subtracted again).

**Real sheet check (before milestone 3)**: on one real Bosta wallet sheet of the reference brand, record here which day each daily row carries, whether VAT is its own row, whether Collected Cash Cycle includes refusal fees, exchange cash, and refunds, and whether a balance column exists; and the line kinds fixed for C5. Not run yet.

**Revision lateness (before milestone 3)**: from spec 0018's mirror after a month of running, record here how many working days after a deposit Bosta's revisions arrived (median and 90th percentile) and the default wait chosen. Not run yet.

**Pilot month (slice 1a done when)**: close the real Bosta month of the pilot, or, if a line still blocks, record the close check. Record here the account, the period, every condition's state with both figures, every judgment by a person, each acceptance with its reason code, who closed it and the close event id, or every blocking line with its reason. Not run yet.
